# 現在値取得の自動化：株価API調査メモ（2026年7月時点）

## 背景

現状、保有銘柄の現在値は手動入力のみ（`useHoldings`に外部API連携なし）。No.8タスクとして、現在値取得を自動化できる株価APIを調査し、導入方針を検討する。実装は本メモの結論をふまえて次段階で行う。

## 調査した選択肢

日本株・投資信託の現在値をNISAポートフォリオアプリから取得する手段として、以下を比較した。

| サービス | コスト | 遅延 | 備考 |
|---|---|---|---|
| J-Quants API（JPX公式） | 無料プランあり | 無料プランは12週間遅延 | APIキー認証。企業財務データも充実。無料プランは現在値表示には実用性が低い |
| yfinance（Yahoo Finance非公式） | 無料 | 約15分遅延 | Pythonライブラリ。ブラウザから直接は呼べず、サーバー経由が前提 |
| kabuステーションAPI（三菱UFJ eスマート証券） | 無料（口座開設要） | ほぼリアルタイム | Windows上でkabuステーション本体の常時起動が必要。早朝に自動ログアウトあり |

## 技術的な制約

本アプリはバックエンドを持たないクライアントオンリーのPWA（localStorage永続化のみ）。この構成のまま株価APIを直接ブラウザから呼び出そうとすると、CORS制約によりほとんどのAPI（yfinance系エンドポイント、J-Quants等）は失敗する可能性が高い。kabuステーションAPIはローカルホストで動作するため個人のPCで開発中に試す分には使えるが、外出先からスマホでPWAを開く運用とは相性が悪い。

## 推奨方針

現時点でこのアプリの規模感（個人利用・銘柄数少数）を踏まえると、以下の段階的な導入を推奨する。

まず、No.10（デプロイ先の決定）で選ぶホスティング先にサーバーレス関数（Vercel Functions や Cloudflare Workers など）を1つ追加し、そこでYahoo Finance系の株価取得を代理実行してCORSを回避する構成にする。これにより無料の範囲で15分程度の遅延はあるが実用的な現在値取得が可能になる。より正確なデータが必要になった場合はJ-Quants APIの有料プランへの切り替えを検討する。

当面は「現在値を手動入力」を残しつつ、銘柄カードに「最終取得」ボタンを追加し、押した時だけサーバーレス関数経由で現在値を取得・上書きする形が実装コストと効果のバランスが良い。常時自動更新（PUSH型）はkabuステーションAPI等口座連携が必要になり、個人開発の初期スコープとしては過大なので見送る。
